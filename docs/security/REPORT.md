# Voyager Trip Manager — security testing report

Status: **DRAFT, round 1 (2026-11-11), development build — not yet the deployed AWS stack.**
Structure from `docs/SECURITY-PLAN.md` §9. Each later round (staging, then pre-production) adds
its results here; the risk register is the live copy in SECURITY-PLAN §8.

## 1. Scope and system

Voyager Trip Manager PWA (`web/`, built with `npm run build:aws`) and its Laravel 13 API (`api/`)
on PostgreSQL, as described in `docs/MIGRATION-PLAN.md`. Not in scope for round 1: the AWS
infrastructure (waiting on the organisation's baseline — `docs/AWS-SECURITY.md`), Zscaler policy,
and the Firebase build being retired.

## 3. Findings

| # | Source | Severity | Finding | Status |
|---|---|---|---|---|
| F1 | Plan review | High | IP-only rate limits would lock out whole offices behind Zscaler | Fixed in design: limits keyed on email/user (R14) |
| F2 | Plan review | High | Background polling would keep sessions alive for ever | Fixed: `X-Background-Poll` + idle/absolute timeout; tested |
| F3 | Plan review | Medium | S3 presigned links bypass one-origin design and are bearer links | Fixed: downloads stream through the API after the access check; tested |
| F4 | Plan review | Medium | Append-only audit tables vs account deletion | Fixed: no foreign keys on audit tables; DB triggers; tested |
| F5 | Plan review | Medium | Anomaly detector would lock out people still polling a trip they left | Fixed: distinct-resource counting; tested |
| F6 | E2E test | Medium | Signed-out request without JSON `Accept` → HTTP 500 (guest redirect to a missing route) | Fixed; regression test added |
| F7 | Header check | Low | Default CORS answered `Access-Control-Allow-Origin: *` | Fixed: CORS disabled (one origin) |
| F8 | Header check | Low | `X-Powered-By: PHP` from the PHP runtime | Fixed for production: `expose_php = Off` (deploy/php.ini), nginx hides it |
| F9 | npm audit | Critical | jsPDF 3.x (path traversal / PDF injection advisories) | Fixed: upgraded to 4.2.1; PDF export re-tested end to end |
| F10 | npm audit | High | Firebase SDK → `@grpc/grpc-js` advisories | Not in the AWS bundle (verified: no Firebase code in `dist-aws`); removed at Firebase decommission (R16) |
| F11 | Larastan | Low | 3 × `abort_unless` given an object instead of a bool | Fixed |
| F12 | Larastan | Low | Unneeded null-safe operators; loose typing of item schemas; template inference on `collect()` | Fixed |
| F13 | Larastan | Low | Default seeder called a factory that does not exist | Fixed: seeder emptied, factory removed |
| F14 | composer audit | — | No advisories | — |
| F15 | Review | Medium | Admin "set-password link" shown to the administrator (account takeover by an insider) | Fixed: link emailed to the person only; tested |
| F16 | Review | Low | Push subscription endpoint is a URL the server calls (SSRF) | Fixed: allow-list of browser push services; tested |

## 4. Risks — mitigated, accepted, open

See SECURITY-PLAN §8 for the full register. Round-1 changes: R14 added and mitigated; R16
(Firebase dependencies, open until decommission) and R17 (container processes run as root inside
the container, open — harden during the AWS build) added. **Owner sign-off is needed on every risk
marked "Accepted?"** before the report is final.
